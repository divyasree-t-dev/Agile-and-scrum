# Day 4 – Doing Scrum: Set 1
## Digital Wallet Application – Mid-Sprint Change

### Project Overview
This assignment demonstrates Scrum sprint planning, backlog management, daily stand-up meetings, handling mid-sprint changes, sprint tracking, and retrospective activities for a Digital Wallet Application.

### Business Scenario
A fintech development team consists of five developers working in a 10-day sprint. On Day 4, the business requested a new feature: **Refund to Wallet**.

The team reviewed the request and adjusted the sprint scope by moving the transaction history story back to the product backlog and adding the refund-to-wallet story.

### Sprint Details
- Sprint Name: Sprint 4 – Digital Wallet
- Sprint Duration: 10 Days
- Team Size: 5 Developers
- Previous Sprint Velocities: 21, 24, 23 Story Points
- Average Velocity: 22.67 ≈ 23 Story Points
- Sprint Capacity: 23 Story Points

### Sprint Backlog

| Story ID | User Story | Story Points |
|---|---|---:|
| US01 | View Wallet Balance | 5 |
| US02 | Add Money to Wallet | 5 |
| US03 | Transfer Money to Another User | 8 |
| US07 | Refund to Wallet | 5 |
| **Total** | | **23** |

### Sprint Goal
Deliver core digital wallet functionality, including balance viewing, adding money, money transfers, and refund-to-wallet processing.

### Tasks Completed
1. Calculated average sprint velocity and selected backlog stories.
2. Broke down user stories into subtasks with hour estimates.
3. Prepared a Day 3 daily stand-up and impediment log.
4. Reprioritised the product backlog based on the mid-sprint change.
5. Tracked sprint progress using the Jira Burndown Chart.
6. Conducted a sprint retrospective and identified improvement actions.
7. Mapped the Definition of Done to the software build pipeline.

### Tools Used
- Jira – Sprint planning, backlog management, task tracking, and burndown reporting.
- Microsoft Word – Assignment documentation.
- Microsoft Excel – Not used; sprint burndown was tracked using Jira.

### Deliverables
- Sprint Backlog
- Daily Stand-up and Impediment Log
- Backlog Reprioritisation
- Jira Burndown Chart Screenshot
- Sprint Retrospective and Action Items
- Definition of Done – Pipeline Mapping

### Key Learning Outcomes
- Understanding Scrum sprint planning and execution.
- Managing scope changes during an active sprint.
- Tracking sprint progress using a burndown chart.
- Identifying and resolving team impediments.
- Applying the Definition of Done in a development pipeline.
